# 과제 8 — 공개 소개와 패스키 비공개 공간

과제 1의 공개 소개 페이지를 유지하면서 `/private`에 개인 공간을 추가했습니다. 기존 소개 원본은 `legacy/assignment1-index.html`에 보관합니다. 결과물은 `https://persona.anseokju02.chatgpt.site`입니다.

## 공개·비공개 경계

- `/`: 누구나 읽을 수 있는 과제 1 소개와 비공개 공간으로 가는 링크. 실제 비공개 메모는 포함하지 않습니다.
- `/private`: 패스키 등록·로그인·관리 UI. 메모 본문은 이 페이지 소스에 포함하지 않고 인증 후 API에서 불러옵니다.
- `GET /api/private`: 서버 세션이 없으면 HTTP 401. 로그인 세션이 있으면 세 가지 메모와 서버 확인 기록을 반환합니다.
- `PUT /api/private`: 동일 출처·서버 세션을 확인한 뒤 메모를 수정합니다. 서버의 D1에 저장됩니다.

## 패스키 흐름

1. 첫 패스키 등록은 사이트 소유자의 ChatGPT 로그인 신원을 서버에서 확인한 경우에만 시작합니다. `OWNER_ACCOUNT_USER_ID`는 배포 환경의 **비밀 변수**로 설정합니다. 이후 추가 등록은 기존 패스키 로그인 세션에서만 가능합니다. 공개 방문자가 첫 등록을 선점할 수 없습니다.
2. `@simplewebauthn/server`가 매번 새 질문을 생성하고, D1에 5분 보관합니다. 브라우저의 질문 식별자는 HttpOnly 쿠키에 담습니다. 확인 시 질문을 원자적으로 삭제해 한 번만 사용합니다.
3. 등록 때 출처·RP ID·질문·사용자 확인을 검증한 뒤 서버에 공개키, 카운터, 전송 방식, 사람이 알아볼 패스키 이름만 저장합니다. 개인키·PIN·생체 정보는 받지 않습니다.
4. 로그인 때 새 질문에 대한 패스키 서명과 카운터를 검증한 뒤 12시간짜리 서버 세션을 만듭니다. 세션 토큰은 HttpOnly·SameSite 쿠키로 주고 서버에는 SHA-256 해시만 저장합니다.
5. 로그아웃은 서버 세션을 삭제합니다. 패스키를 삭제하면 그 패스키의 세션을 폐기합니다. 모두 삭제하면 소유자 확인을 거쳐 다시 첫 등록을 할 수 있습니다.

패스키의 **개인키**는 기기 또는 브라우저의 패스키 관리자에 남습니다. 실제 저장 위치는 사용자가 선택한 기기/동기화 설정에 따라 달라질 수 있으므로 화면에는 사용자 확인용 이름을 별도로 붙입니다.

## 로컬·배포

- Node 22 이상, pnpm 11.25, Cloudflare D1의 `DB` 바인딩이 필요합니다.
- `pnpm install`, `pnpm db:generate`, `pnpm build`로 준비합니다. 새 로컬 DB에는 `drizzle/0000_modern_hellion.sql`을 한 번 적용합니다.
- 배포 환경에 `OWNER_ACCOUNT_USER_ID`를 비밀 값으로 설정합니다. 실제 값은 소스·로그·캡처에 포함하지 않습니다.
- 본 배포는 Sites 빌드가 D1 마이그레이션을 적용합니다. 사이트는 공개 접근으로 유지하되 비공개 API는 앱 세션으로 보호합니다.

## 확인할 장면

1. 로그아웃 상태에서 `/`의 기존 성격·취미·반려견·MBTI·강점이 보이고, `GET /api/private`는 401입니다. 공개 HTML·Network 응답에 비공개 메모가 없습니다.
2. 소유자 신원으로 패스키를 하나 등록하고 로그인합니다. 등록 질문/응답, 공개키 저장과 사람이 알아볼 이름을 확인합니다.
3. 로그아웃 후 같은 질문·변조된 서명으로는 거절되고, 새 질문과 올바른 패스키로만 다시 들어갈 수 있는지 확인합니다.
4. 두 번째 패스키를 등록해 목록에 두 개가 보이는지 확인하고 하나를 삭제합니다. 남은 패스키 로그인은 성공하고 삭제한 패스키 로그인은 거절되는지 확인합니다.
5. 패스키 없이 비공개 API를 직접 열거나 메모 수정을 시도할 때 401/403을 확인합니다.

실제 패스키 팝업, 서로 다른 기기 및 브라우저, 저장 관리자 위치는 소유자가 본인 기기에서 확인해야 합니다. 등록·로그인 성공을 확인하기 전까지 그 결과를 통과로 기록하지 않습니다.
